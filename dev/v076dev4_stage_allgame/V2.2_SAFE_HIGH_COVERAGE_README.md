# V2.2.0 — SAFE HIGH-COVERAGE ENEMY FACTORY RANDOMIZER

The V2.1 log proved the stage mechanism works, but exposed unsafe V2.1 behavior: it changed three Cordelion seabase-boss factories into ordinary enemies (hover, swarmer, crab), and it allowed candidates without proven spawn-point compatibility. That can break an encounter or make enemies appear missing.

V2.2 keeps the cross-planet factory scan, but removes the unsafe fallbacks.

## What changed
- Boss-tier, mount, friendly, unknown, and otherwise non-regular originals are kept native.
- Boss-tier and non-regular candidates are never selected.
- A replacement is made only when the pair passes the compatibility rules AND its spawn-point evidence passes.
- If no candidate passes both checks, the original enemy is retained.
- Latest NO SPAWN / ORIGINAL SPAWNED verdict UIDs remain blacklisted.
- Cross-planet template lookup remains enabled.

This deliberately prioritizes functioning encounters over a misleading 100% replacement count. Coverage will be lower than V2.1, but each attempted change has a defensible compatibility and spawn-point basis.

## Run
Keep the toolkit in the complete project folder and run BUILD_V2_2_SAFE_HIGH_COVERAGE.bat. Drag your local Rift Apart game folder into the prompt. Review COVERAGE_REPORT.md and inventory.csv. The builder creates a new output folder and asks before installing.

## Important
This is still an experimental .stage build and has not been validated in-game. The 8 ms frame-budget errors in the submitted rivet.log are from the live Lua spawner scan path, separate from the .stage file builder. They did not prevent all stage replacements: the log records 46 REPLACEMENT SPAWNED events. The log also records six warnings for one Cordelion mission zone whose patched copy was not the one loaded. V2.2's builder prevents unsafe boss and unverified-spawn replacements, but the runtime budget warning and alternate-zone asset path still need separate investigation.
