# V2.1.0 — FORCE ALL CLASSIFIABLE ENEMY FACTORIES

This is the maximum-coverage experimental mode requested for the next in-game test.

## Run it

Keep this file inside the complete dev/v076dev4_stage_allgame project folder and double-click:

BUILD_V2_1_FORCE_ALL_ENEMIES.bat

Drag the game folder into the prompt. The builder reads the local game archives, scans every zone in the game's DAG, writes a separate build folder, runs the structural checker, and asks before installing.

## What force mode changes

The previous MAX profile only changed spawners when the faction/movement pair, spawn point, and shared-variable ownership rules all passed. That left large groups of enemy factories untouched.

V2.1 adds --force-all-enemies:

- Attempts every classifiable enm_* SunsetSpawnerFactory with one structurally valid Templates plug.
- Resolves existing external template UIDs against the complete scanned actor catalogue when possible.
- Uses globally unique enemy template UIDs from other zones via idx=0xFFFF, so a local replacement anchor is not consumed.
- Prefers compatible faction/movement pairs and spawn-point clue matches; falls back to any available enemy template when no safe candidate exists.
- If the latest runtime verdict says a replacement UID produced NO SPAWN or ORIGINAL SPAWNED, that exact failed UID is blacklisted and the spawner is retried with a different candidate.
- Marks every forced change FORCED-TEST or FORCED-UNVERIFIED in the manifest and report.

## Important coverage boundary

The uploaded inventory scan found:

- 849 factory templates whose kind starts with enm_*.
- 91 veh_* factory templates (kept outside this enemy-only mode because vehicles are a separate asset class).
- 638 other nodes with Template plugs outside SunsetSpawnerFactory. They are diagnostic candidates, not proven enemy spawners, and this build does not blindly rewrite them.
- 82 factory template references are external, and some may not be classifiable if their actor UID cannot be resolved.
- Factories with malformed/multiple Templates plugs, duplicate keys, or unreadable zone data are left untouched.

Therefore this is NOT honestly advertised as 100% of every enemy entity in the game. It is the biggest defensible first test of all classifiable enemy factory spawners. The local scan will produce the exact changed/unchanged counts in COVERAGE_REPORT.md and inventory.csv; those are the numbers to judge coverage, not a guessed percentage.

## Risk and test plan

This mode deliberately relaxes:
- same-faction and movement-group compatibility;
- animation-clue spawn compatibility;
- shared variable owner restrictions.

The resulting .stage can be structurally valid while some enemies fail to spawn, behave incorrectly, or affect a co-owner node. The build checker verifies zone bytes and reference integrity; it cannot prove runtime behavior.

The launcher does not install automatically. Review the report, then choose Y. Keep the backup created by the installer. Test one encounter at a time and retain rivet.log so the next verdict pass can blacklist failures and preserve successes.
